# Incident: a correct Lean proof rejected for a token in a comment-free line

**Date:** 2026-10-19
**Submission:** 2026-10-19T17:52:12Z (task `submitted_at`), verdict read back minutes later
**Loss:** 0.00111744 SOL (0.00111244 claim rent + 0.000005 submit fee), bounty 0.15 SOL refunded to the client
**Outcome:** `state: verified`, `composite_score: 0`, `payment_amount: null` — i.e. rejected and refunded

## What happened

A Lean 4 refutation (`¬ statementProp`) was written for a platform-10 (LeanProof)
bounty, verified locally on the **exact pinned checker environment**
(Lean 4.30.0, Mathlib `c5ea003…`), composed the way the runner composes
(statement prepended, artifact imports hoisted), and checked for the axiom set:

```
'proof' depends on axioms: [propext, Classical.choice, Quot.sound]     # exactly the allowlist
proof : ¬statementProp
lean exit=0, warm rebuild 39 s (policy budget 600 s)
```

The artifact was published, its bytes re-downloaded and compared
(`sha256` equal), the submit transaction simulated and then broadcast. The
attester then returned:

```json
"check_detail": "proof contains forbidden token `scoped` (policy rejects meta commands)",
"composite_score": 0,
"payment_amount": null,
"state": "verified"
```

## Root cause

The artifact began with

```lean
open scoped BigOperators
```

copied from the campaign statement's own header. The checker performs a **static
scan of the artifact source for meta-command tokens and rejects before invoking
Lean**. `scoped` is one of those tokens. The theorem itself was never compiled.

Worse: the line was not even needed. The runner prepends the campaign statement,
whose own `open scoped BigOperators` already puts the `∑` notation in scope —
proven afterwards by removing the line and recompiling: same axioms, same
`proof : ¬statementProp`, exit 0.

## Why the local checks missed it

Two mistakes, both now covered by the test suite:

1. every local check compiled the artifact *as part of the composition*, and the
   composition's statement supplied a legitimate `open scoped` — nothing looked at
   the artifact's **own** source for forbidden tokens;
2. the checker's static stage is undocumented; its rejection reason had to be
   learned the expensive way.

## Fix

* `preflight/tokens.py` — scans the artifact's code (comments stripped, nested
  Lean block comments handled) for meta-command tokens; `scoped` carries the
  verbatim checker message as provenance.
* `tests/artifacts/fail_scoped.lean` — regression: must be rejected.
* `tests/artifacts/ok_comment_mentions_scoped.lean` — must pass: a comment that
  mentions `scoped`/`sorry` is not a command.
* `preflight/compose.py` — composition now also reports the artifact's non-empty
  imports, so the "statement supplies the scope" case is visible instead of implicit.

## Reproducing the rejection locally

```bash
python -m preflight check tests/artifacts/fail_scoped.lean \
    reference/statements/add-zero.lean --no-compile
# [FAIL] forbidden tokens - line 1: forbidden token 'scoped' (observed) - ...
```

## Lesson (the general shape)

A proof-bounty payout has **three** gates, not one: the mathematics (compile),
the proof's dependency hygiene (axioms), and the checker's own static policies
(forbidden tokens, allowed imports, artifact size, time budget). The first gate
is the only one that gets attention; the other two are cheaper to check and
cheaper still to automate. A bounty paid 0.15 SOL was decided entirely by the
third gate.
